CONTENT GUIDEBlog posts

01 · Publish an article

Add a blog post
without changing the design.

One article file and one featured image are enough to get started.

Before using any command in this guide: open the project terminal and run cd idea-bulut-website. Run the commands from the folder containing package.json.

  1. Create the file. Run the command below, or copy content/blog/_template.md to a new file such as your-post-title.md.

npm run new:post "Your post title"

  1. Add the image. Put it in public/images/blog/. In the article, use /images/blog/your-image.jpg — leave out public.

  2. Fill in the settings and write the article. Keep the title at 70 characters or fewer and the optional excerpt at 160 or fewer. Use quoted dates in YYYY-MM-DD format.

---
title: "Your post title"
excerpt: "A short introduction to the article."
date: "2026-10-15"
featuredImage: "/images/blog/your-image.jpg"
imageAlt: "Describe what the image shows"
author: "Idea Bulut team"
tags: ["salesforce-devops"]
draft: true
---

Write a short introduction here.

## Your first section

Write the main article here.

  1. Review, then make it visible. Set draft: false, run npm run check:content, fix any reported issues, then save, commit and push the changes. Build and publish the updated website.

Formatting made easy

## creates a section; ### creates a subsection. Code blocks get a copy button. Tables, quotes, image captions and a > Key takeaway: callout are supported.

Updated automatically

The blog listing, reading time, contents menu, related articles, page address, sitemap, RSS feed and AI-readable files update with the next build.

Editing an existing article? Keep its filename. Add updated: "YYYY-MM-DD" when revising it; use a date on or after the original publication date. Drafts are hidden everywhere.

02 · Publish a product

A new product card.
The same consistent design.

The small icon, description, chips, button and large visual all come from one product file.

npm run new:product "Your product name"

Or copy content/products/_template.md to a new filename. Put the small icon and large visual in public/images/products/, then fill in the file. The example below is for a product with its own external website.

---
name: "Your product"
brand: "Idea Bulut"
description: "Explain clearly what the product does."
tags: ["Free to start", "Your category"]
icon: "/images/products/your-product-icon.png"
visual: "/images/products/your-product.png"
visualAlt: "Describe the product image"
visualBackground: soft
cta:
  label: "Discover your product"
  href: "https://your-product-website.com"
  external: true
order: 30
featured: true
status: coming-soon
hasPage: false
---

Three visibility switches

  • status: live shows the product publicly.
  • featured: true includes a live product in the homepage carousel.
  • hasPage: true creates a product page on this website.

Card details

  • Description: 160 characters maximum.
  • tags are the small label chips.
  • cta controls the button.
  • Background options: soft, white or navy.
Change the order: use 10, 20, 30 and so on. A product set to 15 appears between 10 and 20 on the Products page. The homepage intentionally keeps re:target first.

Ready to show it? Change status to live, run npm run check:content, then save, commit, push, build and publish.

Need a full product page later? Set hasPage: true and use the full template’s optional features, FAQ and main text. For an internal button, use a real internal path and external: false. The two current products stay external: Toolbelt for Copado and re:target.

03 · What has been improved

Clear for visitors.
Readable for search and AI.

The technical foundations help search engines find the site, identify its pages and understand the information on them.

Clear page identity

Titles, descriptions & links

Each content page has its own search title, description and preferred page address. That preferred address is called a canonical URL. Old addresses redirect to an appropriate current destination.

Ready to be read

Content in the page source

Headings, text, links and FAQ answers are already in the HTML. Search engines and AI tools do not have to run the site’s interactive features to read the main information.

Organized information

Structured data

Machine-readable labels describe the business, website, services, breadcrumbs, FAQs, articles, listings and contact page. Future local product pages have their own software-product labels.

Better answers

Consistent FAQ content

The visible service FAQs and their search-engine labels use the same source. Questions use clear headings and direct answers, reducing the risk of conflicting information.

Sharing & accessibility

Images and page previews

Social-sharing titles and images are configured. Blog posts use their featured images. Images use responsive delivery, helpful descriptions where needed and defined dimensions to reduce page movement.

Safer, cleaner delivery

Performance & browser checks

The site uses optimized images, managed fonts, compression, caching and security headers. Keyboard focus, reduced motion and labelled controls are supported. No analytics or tracking pixels were added.

Files that keep discovery up to date

FileWhat it does, simply
/sitemap.xmlA generated list of indexable site pages for search engines.
/robots.txtDocuments crawler access, including named search and AI crawlers.
/llms.txt & /llms-full.txtA concise guide and a fuller content reference for AI tools.
/feed.xmlAn automatically updated RSS feed of published blog articles.

What the terms mean: SEO supports search discovery; AEO supports understanding answers; GEO supports understanding by generative AI tools. These are technical improvements, not a guarantee of rankings, traffic, indexing or AI citations.

05 · The technical essentials

Know where things live.
Publish with confidence.

The site uses Next.js, React and TypeScript. Main pages and published content are prepared at build time. A Next.js production server delivers them, handles redirects and optimizes images. Blog and product content need no separate database or CMS dashboard. Core content needs no environment variables.

What you want to changeWhere to look inside idea-bulut-website
Articles and product detailscontent/blog/ and content/products/
Imagespublic/images/blog/, products/ and brand/
Site-wide detailssrc/config/site.ts
Menu and footer linkssrc/config/navigation.ts
Service FAQ answerssrc/data/faqs/

Hide or remove content

Hide an article with draft: true. Hide a product with status: coming-soon. To remove one permanently, delete its file and update links pointing to it. Publish an updated build for the change to go live.

Keep existing links working

The filename becomes the page’s address. Avoid renaming a published file. If its address must change, ask the developer to add a redirect from the old one.

The repeatable publishing checklist

Save the content and images → run the checks → fix errors → commit and push → build and publish. Saving a file alone does not update the live site.

npm run check:content     # Check the content files
npm run lint              # Check code quality
npm run typecheck         # Check TypeScript
npm run build             # Create the production build

Content checks run automatically before every production build. More commands are in the README.

Before treating the website as launch-ready

  • Approve the legal details. Privacy and Terms are still drafts and remain excluded from indexing. Unresolved placeholder-dependent sentences are hidden, not replaced with invented facts.
  • Connect message delivery. The contact form is intentionally disabled until delivery is configured. Discovery-call booking uses Google Calendar.
  • Confirm the live domain. The configured default is https://ideabulut.com. Match the published domain to that setting; the setting alone does not prove the site is live.
